# 魔方模型

魔方模型解释了：为什么在复杂 AI 协作中，门禁不是可有可无的流程负担。

它用魔方作为参考对象，因为魔方是一个巨大但有结构的状态空间。

## 关键区别

魔方不是因为状态空间小才可解。魔方可解，是因为：

- 当前状态可见；
- 合法操作明确；
- 错误路径可以排除；
- 目标状态明确；
- 解法会约束下一步动作。

如果没有这些事实，解魔方就会变成盲搜。

同样原则适用于软件工作、设计工作、发布工作和 AI agent 工作流。

## 第一层：随机魔方状态 vs 受控求解

标准 3×3×3 魔方大约有：

```text
4.3 × 10^19
```

个可达状态。

但一旦当前状态已知，并使用合法解法约束，任务就不再是在所有状态里随机遍历。

重点不是“所有真实工作流都是魔方”。重点是：状态与约束会改变搜索问题本身。

## 第二层：通用工作流分支

假设一个复杂任务需要连续 `n` 个正确步骤。

没有门禁时，每一步可能有 `B` 个看似可行的选择：

```text
无约束搜索空间 = B^n
```

有门禁时，事实、SOP、KnownBugRules 和阶段检查会把每一步压缩到 `b` 个有效候选选择：

```text
受控搜索空间 = b^n
```

压缩比例为：

```text
(B / b)^n
```

如果 `B = 15000`，`b = 15`，`n = 20`，那么：

```text
(B / b)^n = (15000 / 15)^20 = 1000^20 = 10^60
```

再结合魔方参考尺度，差异可以达到：

```text
10^78 到 10^79
```

这个数字不是产品宣传语，而是尺度论证。

它说明：缺少状态和约束，不只是增加一点风险，而是可能把一个可求解的工程流程变成不可承受的搜索问题。

## 实践结论

每一次让 AI 在缺少事实、当前状态、错误记忆或阶段约束的情况下行动，都会扩大工作流的搜索空间。

每一个有效门禁，都会压缩这个空间。

因此，门禁不是官僚流程。门禁是求解条件。
