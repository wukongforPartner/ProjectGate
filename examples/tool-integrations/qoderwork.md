# QoderWork Integration Template

Status: L1 instruction integration plus L2 workflow protocol.

## Integration level

- L1 Instruction File Integration: advisory behavior shaping inside QoderWork.
- L2 CLI Workflow Integration: enforceable only when ProjectGate CLI / TaskRun / stage gate / delivery check are actually used outside or through a verified bridge.
- L3 Adapter / MCP Integration: future / unverified for QoderWork unless a real QoderWork API, MCP, or hook interface is confirmed.

## Instruction file

Use a QoderWork Skill package generated by `adapters/projectgate_qoderwork_adapter_v0_1`.

The package must include:

- `SKILL.md`
- `L2_WORKFLOW.md`
- `STAGE_REPORT_TEMPLATE.md`
- `GATE_RESULT_TEMPLATE.md`
- `UNSUPPORTED_GATES.md`
- `references/core/`
- `references/project/`

## Required workflow

For real work, QoderWork must not claim completion from instructions alone.

1. Create or reference a ProjectGate TaskRun.
2. Produce a stage report.
3. Run ProjectGate stage gate.
4. Continue only after `PG_STAGE_GATE=PASS`.
5. Run commands through `pg exec` when command evidence is required.
6. Claim final completion only after `PG_DELIVERY_CHECK=PASS`.

## Boundary

A QoderWork Skill alone cannot enforce file writes, shell commands, commits, deployments, or releases. Those actions are enforceable only inside a ProjectGate-controlled flow.
